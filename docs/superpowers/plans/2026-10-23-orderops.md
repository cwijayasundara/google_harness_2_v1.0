# OrderOps Implementation Plan

> Implement inline using executing-plans, with failing tests before production changes.

**Goal:** Ship a reproducible OrderOps benchmark for Pi-driven harness evolution.

**Architecture:** Separate generated public tasks, editable harnesses, online
experiment scheduling, and private offline grading. Reuse the existing controller,
Pi editor, sandbox and ledger; put experiment-specific policy in OrderOps modules.

**Tech Stack:** Python 3.12, Pydantic, pytest, existing Deep Agents/Pi Durable.

**Spec:** ../specs/2026-10-23-orderops-design.md

## Global constraints

- Integer GBP pence; no hidden scoring in online refinement.
- Three primary arms plus an explicitly attempt-matched retry control.
- Frozen holdout execution; shared explicit spending cap; resumable records.
- Preserve legacy tests without shipping the portfolio harness as an example.

## Review focus

- Retransmitted events and transaction status transitions must not double count.
- Empty, duplicate, malformed and boolean amounts must not pass the grader.
- Changed source/configuration must reject resume before altering run metadata.
- A failed selection must keep the previous bundle; future lessons must stay hidden.
- Missing held-out executions must lower success rather than disappear.

### Task 1: Public cases and private grading

Files: orderops/contracts.py, cases.py, score.py; tests/test_orderops_cases.py,

Interfaces: generate_suite(public_root, private_root, seed, dev_count, holdout_count)
creates TaskSpec files and separate answers.json. score_case(task, artifacts,
expected) returns metrics; evaluate_experiment(run_dir, answers_path, output)
reports all arms. The evaluator consumes answers, not generation helpers.

Independent review identified and drove fixes for executor-image answer-code
exposure, budget stage grouping/release, selector accounting, actual retry count
matching, and evaluator output contamination. Regression tests cover the fixes.

smoke suite generated at runs/orderops-smoke (6 dev, 2 holdout).

Docker image build/inspection and live Pi/model runs remain unverified: Docker
is stopped and no paid-run cap was supplied. The opt-in Docker isolation test
checks that answer generation/scoring cannot be imported or read from the rebuilt
image. No paid model calls were made.

Implementation decisions: CLI first; preserve legacy portfolio code and archived
adoptions while moving its removed seed to test fixtures only. Retry control uses
actual local execution counts when local is enabled, otherwise scheduled 4*k;
this matches attempts, not dollars. Local holdout freezes the last development
case's selected bundle. Scores are never fed back into refinement.
